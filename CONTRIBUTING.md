# Участие в разработке

## Основные правила

- Не добавляйте DICOM, NIfTI, клинические таблицы, ключи и иные данные пациента в git, даже если они кажутся обезличенными.
- Любое изменение признака, порога, предобработки или модели требует обновления версии конвейера и model card.
- Не описывайте исследовательские метрики как доказательство клинической готовности.
- Бизнес-логика не должна зависеть от WPF, DICOM-библиотеки или конкретного ML-движка.
- Логи и исключения не должны содержать ФИО, идентификаторы исследования, accession number или пиксельные данные.

## Команды

Требуется .NET 10 SDK — версия зафиксирована в `global.json`. Эти команды обязательны и выполняются в CI при каждом push и pull request:

```powershell
dotnet restore Hydrocephalus.slnx
dotnet format Hydrocephalus.slnx --verify-no-changes
dotnet build Hydrocephalus.slnx --configuration Release
dotnet test Hydrocephalus.slnx --configuration Release
```

Сборка идёт с `TreatWarningsAsErrors`, поэтому предупреждение анализатора останавливает CI. Перед отправкой изменений прогоняйте `dotnet format` без `--verify-no-changes`, иначе форматирование уронит сборку.

Python-контур живёт в `ml/` и требует Python 3.12. Команды выполняются из каталога `ml/` и тоже обязательны в CI:

```powershell
python -m pip install --no-deps -e .
python -m pip install pytest ruff mypy
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest
```

`mypy` работает в строгом режиме: функция без аннотаций останавливает проверку. Стек обучения (torch и прочее) ставится отдельно через `pip install -e ".[training]"` — он не нужен ни линтерам, ни тестам.

## Изменения ML

Pull request, меняющий ML-конвейер, должен содержать:

1. идентификатор набора данных и правила patient-level split;
2. версию конфигурации, seed и хеш артефакта;
3. метрики с доверительными интервалами;
4. результаты по центрам, сканерам, полу, возрастным группам и важным дифференциальным классам;
5. анализ ошибок, калибровки и отказов QC/OOD;
6. обновлённую model card и запись в журнале решений.

## Definition of Done

- тесты и статический анализ проходят локально и в CI;
- новые пути обработки имеют тесты на отмену и ошибку;
- изменения, затрагивающие PHI, прошли privacy review;
- пользовательский текст не обещает автономную диагностику;
- документация и трассировка требований обновлены.

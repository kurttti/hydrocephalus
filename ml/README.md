# ML workspace

Исследовательский контур обучения и экспорта моделей. Он не поставляется пользователю как часть Windows-клиента.

## Планируемая структура

```text
ml/
├── configs/          # версионированные параметры экспериментов
├── src/
│   ├── data/         # manifests и transforms
│   ├── segmentation/ # обучение сегментации
│   ├── features/     # измеримые признаки
│   ├── classification/
│   ├── evaluation/
│   └── export/
├── tests/
└── model_cards/
```

Папки создаются вместе с первым исполняемым модулем, чтобы пустая структура не маскировала отсутствие реализации.

## Правила

- конфигурация является частью результата эксперимента;
- доступ к данным идёт через manifest, а не жёстко заданные пути;
- notebook не является production-пайплайном;
- экспорт ONNX проверяется на численное соответствие исходной модели;
- model card обязательна для любого кандидата, передаваемого в приложение;
- веса и данные не коммитятся в git.

Методические требования: [docs/ml/README.md](../docs/ml/README.md), критерии оценки: [docs/validation/README.md](../docs/validation/README.md).

## Манифест датасета

Доступ к данным идёт через манифест — файл, который **создаёт приложение на .NET**, а не собирает этот пакет. Разбор DICOM, вывод геометрии и уровня входа, псевдонимизация уже реализованы и покрыты тестами в `Hydrocephalus.Infrastructure`. Второй разбор на Python означал бы две реализации, которые могут разойтись, и датасет, построенный на геометрии, отличной от той, по которой приложение измеряет. Расхождение проявилось бы не сбоем, а метриками, которые нельзя перенести на продукт.

Схема версии `1.0.0`:

```json
{
  "schema_version": "1.0.0",
  "series": [
    {
      "series_id": "3f2a…",
      "study_id": "9b71…",
      "subject_id": "c40e…",
      "tier": "Extended",
      "weighting": "T1",
      "contrast_enhanced": false,
      "slice_count": 176,
      "voxel_spacing_mm": [0.9, 0.9, 1.0]
    }
  ]
}
```

Все идентификаторы псевдонимные: исходных UID и имён в манифесте нет и быть не может. Референсного диагноза в нём тоже нет — метки живут во внешнем защищённом реестре и соединяются с манифестом по `subject_id`.

Уровни входа: `Unusable`, `Baseline`, `Extended` — в порядке возрастания.

## Что уже работает

- `manifest` — чтение и строгая проверка манифеста; любая неполная запись отвергается, а не принимается молча;
- `splitting` — разделение по пациентам с защитой от утечек;
- `dataset` — соединение с метками, разделение и сводка состава.

Сборка датасета отказывает в трёх случаях, каждый из которых даёт метрики, которые ничего не значат и при этом выглядят нормально: противоречивые метки одного пациента, класс, отсутствующий в одной из выборок, и запрошенная, но пустая выборка.

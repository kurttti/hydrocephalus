# ADR 0009: Внешняя предобученная модель сегментации желудочков

- Статус: accepted (владелец проекта, 2026-09-19)
- Дата: 2026-09-19
- Владельцы: владелец проекта (решение по лицензии и назначению), инженерная команда

## Контекст

Базовая сегментация без обучения (`baseline-1.3.0`) измеряет 7 из 12 клинических объёмных T1 и 414 из 581 серии IXI T1 (`docs/data/README.md`). На трёх оставшихся клинических сериях (шумная с пикселем 0,41 мм, низкоконтрастная, крайняя гидроцефалия) классические приёмы исчерпаны: сглаживание, поиск ядер при разной толщине и маска мозга без обучения либо не помогают, либо дают неверный объём, который метод не может отличить от верного. Две серии — тонкие прицельные блоки; их отказ правильный и моделью не лечится.

Обучать свою модель не на чем: пациентов с пригодной неконтрастной 3D-серией 38 (`docs/data/README.md`), разметки нет. Остаётся взять опубликованную предобученную модель. Архитектура это уже предусматривает: `segmentation.onnx` в подписанном пакете `.hcmp` (ADR 0004), инференс ONNX Runtime внутри процесса за `IInferenceEngine` (ADR 0002), установка и откат только действием администратора (ADR 0008).

Решающий вопрос здесь — не точность, а **лицензия весов**. Лицензия кода к весам не относится: веса распространяются отдельно, и там, где их лицензия не указана, права на использование не предоставлены.

## Решение (предлагаемое)

1. **Первая модель — FastSurfer VINN.** Это единственный кандидат, у которого и код, и веса под разрешительной лицензией (Apache-2.0), допускающей встраивание в продукт с сохранением уведомлений об авторских правах. Из её разметки берутся только метки желудочков (боковые, нижние рога, III, IV).
2. **Назначение — исследовательское.** Результат модели, как и базовой сегментации, помечается `Questionable`, пока не пройдена валидация. Это совпадает и с оговоркой авторов FastSurfer, и с текущим статусом всего метода.
3. **Параллельно запросить у авторов VParNet лицензию на веса.** Это наиболее профильная модель, но без явного разрешения её встраивать нельзя. Запрос отправляет владелец проекта: это его исследование и его переписка.
4. **SynthSeg в составе FreeSurfer и HD-BET не использовать** в приложении: их лицензии запрещают коммерческое и клиническое применение. Автономную версию SynthSeg — только после письменного разрешения авторов на веса.
5. **Поставка — по ADR 0004 и 0008.** Веса конвертируются в ONNX в обучающем контуре `ml/` (Python остаётся только там, ADR 0002), упаковываются в `.hcmp` вместе с `model-card.md` и текстом лицензии Apache-2.0 с перечнем авторов. В репозиторий веса не попадают; CI их не скачивает.
6. **Место в конвейере.** Модель не заменяет базовую сегментацию, а работает рядом с ней. Если обе дали объём и расходятся больше заданной доли, результат помечается для просмотра. Правило расхождения фиксируется после валидации, а не заранее.

## Рассмотренные варианты

- **Обучить свою модель** — отклонено сейчас: 38 пациентов без разметки; вернуться, когда появится разметка (roadmap).
- **Запускать FastSurfer/SynthSeg как внешний Python-процесс** — отклонено для приложения (ADR 0002: Python не входит в клиническую поставку). Допустимо в исследовательском контуре `ml/` на машине владельца данных — с теми же правилами, что для пакетного замера: вывод только в `%LOCALAPPDATA%`, в консоль только агрегаты.
- **Ограничиться ручной разметкой трёх серий** — дешевле сейчас, но не решает задачу для новых пациентов.

## Риски

- **FastSurfer на больших желудочках** может ошибаться именно в той группе, ради которой он нужен: в детской выборке Dice падал с ростом объёма желудочков. Поэтому валидация на расширенных желудочках обязательна до любого клинического вывода.
- **Предобработка.** FastSurfer ожидает изотропные 0,7–1,0 мм; часть клинических серий к этому приводится ресэмплингом, серии толще 1,5 мм не подходят вовсе — для них остаются линейные индексы.
- **Воспроизводимость ONNX.** Конвертированная модель обязана давать те же метки, что исходная PyTorch-модель, на контрольных сериях; расхождение — блокирующая ошибка конвертации.
- **Нативные зависимости ONNX Runtime** попадают в установщик и SBOM (ADR 0002).

## План проверки

1. На публичных данных (IXI) — сравнить объёмы желудочков модели и базовой сегментации на 414 сериях, где обе дают объём; посмотреть маски серий с наибольшим расхождением.
2. На 12 клинических объёмных T1 — объёмы и просмотр масок во временной папке сессии (разрешение владельца данных от 2026-09-14), в репозиторий — только агрегаты.
3. Совпадение ONNX и PyTorch по меткам на контрольных сериях.
4. Время инференса на CPU для серии 256×256×176 — ориентир для интерфейса.

## Решение владельца проекта (2026-09-19)

1. **FastSurfer VINN принят** первой моделью; назначение результатов — исследовательское.

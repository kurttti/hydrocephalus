# ADR 0001: WPF и поддерживаемая версия .NET LTS

- Статус: proposed
- Дата: 2026-09-02
- Владельцы: инженерная команда

## Контекст

`docs/windows/README.md` уже фиксирует направление «.NET LTS и WPF для стабильного настольного интерфейса», но конкретная версия .NET не закреплена. Solution ещё не создан (`CONTRIBUTING.md`: команды `dotnet restore/build/test` «станут обязательными после появления solution»), поэтому версию нужно выбрать до старта M1.

Требования, влияющие на выбор: офлайн-работа на Windows 10/11 x64, CPU-only режим обязателен, GPU — опционально через ONNX Runtime, длительный жизненный цикл клинического ПО (годы поддержки без вынужденных мажорных апгрейдов между релизами пилота).

## Решение

Использовать **.NET 10 (LTS, выпущен ноябрь 2025, поддержка до ноября 2028)** как целевую платформу для `Domain`, `Application`, `Infrastructure`, `Inference` и `Desktop`. UI-слой `Desktop` — **WPF** с MVVM (без сторонних тяжёлых UI-фреймворков на MVP) и dependency injection через `Microsoft.Extensions.DependencyInjection`.

## Рассмотренные варианты

- **.NET 8 (LTS)** — отклонено: поддержка заканчивается в ноябре 2026, то есть уже сейчас находится в последних месяцах жизненного цикла; переход на новую LTS потребовался бы почти сразу после старта разработки.
- **.NET 9 (STS)** — отклонено: не-LTS релиз с коротким окном поддержки, не подходит для медицинского ПО с длинным циклом валидации.
- **WinUI 3 / MAUI вместо WPF** — отклонено для MVP: WPF даёт наиболее зрелую поддержку для desktop, DPI-масштабирования 125–200% и клавиатурной навигации из `docs/windows/README.md`; меньше риска незрелых компонентов на старте.
- **Avalonia (кроссплатформенный XAML)** — отклонено: MVP ограничен Windows 10/11, кроссплатформенность не входит в текущий intended use.

## Состояние среды на момент решения

Проверено на машине разработки 2026-09-02:

- установлены рантаймы `Microsoft.NETCore.App` 6.0.36, 8.0.14, 9.0.3, 10.0.5–10.0.9 и `Microsoft.WindowsDesktop.App` 9.0.3, 10.0.5+ — то есть рантайм .NET 10 и WPF-компонент присутствуют;
- при первой проверке .NET SDK отсутствовал (`dotnet --list-sdks` пуст, `dotnet --version` → «No .NET SDKs were found»);
- **устранено в тот же день:** установлен .NET SDK **10.0.400** (`winget install Microsoft.DotNet.SDK.10`), `dotnet --version` возвращает `10.0.400`.

Наличие .NET 10 SDK — предусловие первой задачи M1; на машинах CI и у новых участников оно проверяется явно, а не предполагается.

## Последствия и риски

- Требуется .NET 10 SDK на машинах разработки и CI; на текущей машине разработки он отсутствует (см. выше), Windows-образы CI также потребуют явной установки нужной версии.
- `global.json` фиксирует major-версию SDK, чтобы сборка падала явно при несовпадении, а не молча собиралась другой версией.
- Переход на будущую LTS (следующая ожидается в 2027) закладывается заранее как отдельный ADR, а не выполняется по факту устаревания.
- WPF ограничивает будущую кроссплатформенность — фиксируется как осознанный компромисс для MVP, а не постоянное архитектурное решение.

## План проверки

- `dotnet --version` в CI совпадает с зафиксированной версией; сборка падает при несовпадении major-версии.
- Synthetic end-to-end test (M1) проходит на .NET 10 в CI на Windows-раннере.
- Ревизия ADR при объявлении следующей .NET LTS или при обнаружении блокирующей проблемы поддержки.

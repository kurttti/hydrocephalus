# Журнал решений

Архитектурные решения (ADR) добавляются отдельными Markdown-файлами по шаблону `NNNN-краткое-название.md`.

## Шаблон

```markdown
# ADR NNNN: Название

- Статус: proposed | accepted | superseded
- Дата: YYYY-MM-DD
- Владельцы: роли/команда

## Контекст
## Решение
## Рассмотренные варианты
## Последствия и риски
## План проверки
```

Все восемь находятся в статусе `proposed` и требуют утверждения: ADR 0003 и 0006 дополнительно проходят privacy review, ADR 0005, 0007 и 0008 — согласование с клинической командой.

**Фактическое состояние расходится с этим условием, и это записано намеренно.** Условие «утвердить до старта M1» не выполнено: M1 и M2 закрыты, M3 закрыт кроме DESH-компонентов, и всё это реализовано против ADR в статусе `proposed`. Реализация опиралась на них как на решения, но решениями команды они пока не стали.

Реализовано против конкретных ADR:

| ADR | Что реализовано |
|---|---|
| 0001 | solution на .NET 10 и WPF-клиент |
| 0003 | fo-dicom, профиль деидентификации, переименование файлов и папок; в самом ADR добавлен раздел «Состояние реализации» с тремя отклонениями, требующими решения privacy-ревьюера |
| 0005 | канонический JSON-слой отчёта; PDF/A не реализован |
| 0007 | просмотрщик MPR, оверлеи, подписи сторон; ресэмплинг к изотропной сетке есть, косой реформат — нет |
| 0002, 0004, 0006, 0008 | не реализованы: ONNX, model package, шифрование и обновление модели ждут M4 и далее |

Отдельно: по ADR 0006 рабочая копия создаётся с ограниченным ACL, но **не шифруется**, TTL не применяется и осиротевшие каталоги при старте не удаляются. Это самое заметное расхождение между заявленным и сделанным.

ADR 0001–0006 закрывают список первых решений из этого файла, ADR 0007 и 0008 — оставшиеся пункты раздела «Открытые решения» в [архитектуре](../architecture/README.md).

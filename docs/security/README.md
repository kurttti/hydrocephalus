# Безопасность и приватность

## Активы

- DICOM/NIfTI и метаданные пациента;
- клиническая разметка и референсный диагноз;
- model package и конфигурации порогов;
- отчёты врача и журнал аудита;
- ключи подписи и обновления приложения.

## Основные угрозы

| Угроза | Базовая мера |
|---|---|
| Утечка PHI через лог/ошибку | allowlist полей, структурированные redacted-логи |
| Burned-in annotations | автоматическое обнаружение + ручной контроль |
| Подмена модели | подпись, SHA-256, manifest совместимости |
| Злонамеренный DICOM | лимиты размера/глубины и числа файлов при обходе источника, безопасный парсер; отдельного карантинного каталога нет — источник читается по месту (ADR 0006) |
| Остаточные временные данные | защищённый каталог и гарантированная очистка |
| Несанкционированный экспорт | роли, подтверждение, аудит и политика назначения |
| Сетевой вывод данных | офлайн по умолчанию, allowlist интеграций |
| Ошибочная уверенность модели | QC/OOD, калибровка, отказ от ответа, human-in-the-loop |

## Правила реализации

- секреты не хранятся в исходном коде и пользовательских настройках в открытом виде;
- crash dump и diagnostic bundle проходят очистку PHI;
- доступ к локальному кэшу ограничивается учётной записью/службой приложения;
- отчёт различает исходные данные, вычисленный результат и ручной комментарий;
- audit log защищается от незаметного редактирования **и читается в приложении
  вместе с проверкой цепочки**: журнал, который никто не читает, ни разу
  не проверяется на той машине, где ведётся. У целостности названа её граница —
  удаление хвоста оставляет остаток корректным, поэтому наружу отдаётся хеш
  последней записи для сравнения с якорем, сохранённым вне журнала;
- **чтение журнала — отдельное право**, и есть оно только у администратора.
  Журнал показывает работу всей установки, данных пациента не содержит и доступ
  к нему не вытекает из права разбирать один случай. Отказ в чтении
  записывается, разрешённое чтение — нет: событием является превышение
  полномочий;
- **в записи журнала попадают все поля события.** Кто пытался, какой вариант
  отчёта ушёл наружу и что не удалось удалить при уборке — три вопроса,
  ради которых журнал ведётся, и запись без этих полей не отвечает ни на один;
- зависимости и нативные библиотеки регулярно сканируются, для release создаётся SBOM.

Перед клиническим пилотом требуется формальная модель угроз и проверка применимых требований законодательства и регулятора в целевой юрисдикции.

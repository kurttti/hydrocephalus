# Передача проекта

Чего нет в репозитории, как это восстановить и с чего продолжать. Документ нужен
на случай, когда работа переносится на другую машину или в другую среду: кода
одного мало, и важная часть состояния лежит вне git намеренно.

## Что лежит вне репозитория и почему

| Что | Где | Почему не в git |
|---|---|---|
| Снимки выборки | `D:\` — шесть принятых папок | данные пациентов; имена папок содержат фамилии |
| Публичные наборы | `D:\Публичные наборы` (IXI, ICBM152, FastSurfer) | вес; читаются как есть, архивы не распаковываются |
| **Соль псевдонимизации** | `%LOCALAPPDATA%\Hydrocephalus\secrets\pseudonym-salt.bin` | **секрет**; без неё псевдонимы не сойдутся ни с отчётами, ни с группами |
| Замороженный обезличенный набор | `%LOCALAPPDATA%\Hydrocephalus\dataset` | 4,4 ГБ; **выводится заново** из `D:` при той же соли |
| Отчёты об измерениях | `%LOCALAPPDATA%\Hydrocephalus\reports` | записи по пациентам; неизменяемые версии |
| Журнал аудита | `%LOCALAPPDATA%\Hydrocephalus\audit\audit.log` | сцеплен хешами; обрыв цепочки обнаруживается |
| Накопленные решения и находки | заметки памяти помощника | не код; переносятся файлами отдельно |

**Соль — главное.** Все псевдонимы — пациента, исследования, серии — выводятся из
неё и из исходных полей DICOM. С другой солью прежние отчёты не свяжутся с
новыми измерениями, а набор не свяжется с группами сравнения. Терять её нельзя,
публиковать — тем более.

## Порядок восстановления

1. **Код.** `git clone` с удалённого репозитория либо разворачивание бандла:
   `git clone hydrocephalus.bundle hydrocephalus`.
2. **Среда.** .NET 10 SDK (версия закреплена в `global.json`); для
   исследовательского контура — Python и `ml/.venv` по `ml/README.md`.
   Тесты запускаются **в Release**: Smart App Control блокирует сборки Debug.
3. **Соль.** Положить `pseudonym-salt.bin` в
   `%LOCALAPPDATA%\Hydrocephalus\secrets\`. Приложение создаёт новую, если файла
   нет, — и это худший исход: расхождение обнаружится не сразу.
4. **Отчёты и журнал.** Положить `reports` и `audit` туда же, если нужна история
   измерений.
5. **Набор.** Пересобрать, а не копировать:

   ```
   Hydrocephalus.DatasetBuild --overwrite "иНТГ=D:\МРТ иНТГ" ^
       "иНТГ=D:\Для А.В. Станишевского" "Контроли=D:\Контрольная"
   ```

   При той же соли результат совпадает: 28 пациентов иНТГ в 31 исследовании,
   27 контролей, 12 662 файла (см. `docs/data/README.md`). В замороженном наборе
   контролей с 2026-10-10 на одного меньше: исследование, снятое по протоколу
   позвоночника, исключено решением владельца данных.

## Чем проверить, что всё сошлось

- `dotnet build -c Release Hydrocephalus.slnx` и `dotnet test -c Release` — тесты
  должны пройти целиком;
- `dotnet format Hydrocephalus.slnx --verify-no-changes` — без замечаний;
- `Hydrocephalus.MeasurementSummary` — должен увидеть 57 исследований набора
  (было 58 до исключения 2026-10-10); если видит 0, соль другая либо набор
  не собран;
- `Hydrocephalus.Inventory` по шести папкам `D:` — числа сверяются с
  `docs/data/README.md`.

## Где продолжать

Состояние вех — в `docs/roadmap.md`, раздел «Состояние». Главное в двух словах:

**Приложение измеряет само 34 исследования из 57** (было 6 до 2026-10-08
и 24 после него).
Прежняя причина отказов установлена и измерена: пороговая сегментация отказывала
на 35 — не из-за толщины среза, а потому, что расширенные желудочки связаны
с бороздами и цистернами через частичный объём: вся система выходит одной
областью, касающейся поверхности, и правило глубины отбрасывает её целиком.
Подробности и числа — в `docs/data/README.md`.

Против этого в проекте построены три ступени отбора (глубина, ядра, ядра на
сглаженном объёме); их пределы там же описаны. Принятое решение на этот
случай — **ADR 0009, внешняя предобученная модель, статус `accepted` от
2026-09-19**. С 2026-10-08 она работает внутри приложения: ONNX Runtime за
интерфейсом `IVentricleSegmentation`, серии T1 размечает модель, остальные
взвешенности остаются пороговому пути. Веса берутся из того же проверочного
прохода, которым сошлись хеши пакета, — распакованного файла на диске не
возникает (ADR 0004).

Чего не хватает для выпуска: пакет подписан **пробным** ключом, а доверенный
открытый ключ читается из файла в профиле пользователя. Для выпуска он должен
быть встроен в приложение — файл в профиле правит тот же, кто подсовывает
пакет. Удаление старых версий модели не реализовано.

Что ждёт решения владельца данных, а не работы: восемь ADR в статусе `proposed`,
определение референсного стандарта диагноза (без него не начинается M4) и срок
хранения замороженного набора.

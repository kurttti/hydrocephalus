# Данные и разметка

## Допустимые данные

Репозиторий хранит только схемы, словари, синтетические примеры и тестовые данные, на публикацию которых есть явное разрешение. Реальные DICOM/NIfTI и таблицы пациентов располагаются в контролируемом внешнем хранилище.

На практике исходная ретроспективная выборка сейчас разбросана по нескольким независимо собранным папкам на внешнем диске (разные экспорты/периоды сбора), а не в одном едином хранилище, и продолжает пополняться. Это должно быть консолидировано в единую контролируемую структуру (см. «Снимок текущей ретроспективной выборки» ниже) до перехода к обучению модели — иначе один и тот же пациент, случайно попавший в несколько источников, рискует оказаться сразу в нескольких выборках split'а.

## Предлагаемая модель исследования

```text
Study
├── pseudonymous_subject_id
├── center_id / scanner_vendor / field_strength
├── acquisition_date_bucket
├── series[]
│   ├── modality / sequence_type
│   ├── geometry / voxel_spacing / orientation
│   └── source_hash
├── reference_standard
│   ├── diagnosis_class
│   ├── confidence
│   ├── adjudication_status
│   └── evidence[]
├── annotations[]
└── split_id
```

`split_id` назначается на уровне пациента до получения производных изображений. Один пациент, его повторные исследования и пред-/послеоперационные серии не могут оказаться в разных выборках.

**Правило дедупликации пациентов:** `pseudonymous_subject_id` вычисляется по техническим DICOM-идентификаторам (PatientID + PatientName + PatientBirthDate), а не по имени папки. Обнаруженный на практике случай: при отсутствии всех трёх полей одновременно (реально встречается примерно у половины файлов выборки) наивное хеширование пустой строки склеивает разных пациентов в одного. Если поля идентификации отсутствуют, запись должна считаться уникальным пациентом по умолчанию (никогда не мержится с другой записью без совпадения хотя бы одного непустого поля) — ложное объединение опаснее, чем недо-объединение, так как искажает patient-level split.

## Приёмка серии

Проверяются:

- тип последовательности и полнота 3D-объёма;
- размеры, шаг вокселя, ориентация и непротиворечивость DICOM-геометрии;
- движение, обрезание головы, шум, bias field и выраженные артефакты;
- наличие контраста/имплантов/послеоперационных изменений (в реальной выборке постконтрастные T1-серии часто идут в паре с неконтрастной серией того же пациента и требуют явного отделения по описанию серии, а не только по тегу);
- соответствие диапазонам, использованным при обучении;
- дубликаты по хешу и метаданным;
- корректность единиц в технических тегах — на практике встречаются заведомо ошибочные значения `MagneticFieldStrength` (например, на порядки завышенные из-за путаницы единиц у отдельных производителей) — такие значения нормализуются или помечаются как недостоверные на этапе приёмки, а не используются как есть.

Каждое исключение получает машинно-читаемый код и человекочитаемое объяснение.

## Деидентификация

1. Импорт выполняется в карантинную область.
2. DICOM-теги обрабатываются по утверждённому профилю, включая private tags.
3. Проверяются burned-in annotations и нестандартные поля производителя.
4. UID заменяются согласованно, даты сдвигаются детерминированно внутри пациента.
5. **Имена файлов и папок деидентифицируются наравне с DICOM-тегами.** В исходном сборе данных папки и файлы на практике называются по фамилии пациента (иногда с дополнительными пометками вроде рабочего диагноза или телефона) — это PHI независимо от содержимого самих DICOM-тегов. Деидентификация должна переименовывать директории/файлы в псевдонимные ID на этапе импорта в карантин, а не полагаться на очистку только внутренних тегов.
6. Исходная и рабочая копии связываются только во внешнем защищённом реестре.
7. Экспорт в ML-контур разрешён после автоматической и выборочной ручной проверки.

## Разделение и версии

- train/validation/test делятся по пациентам, а для внешнего теста — по центру;
- финальный test set замораживается до выбора модели и порогов;
- датасет получает неизменяемый manifest с хешами и причинами включения;
- преобразования версионируются вместе с моделью;
- статистика состава публикуется без возможности обратной идентификации.

Пересчитано 2026-09-06 утилитой `tools/Hydrocephalus.Inventory` по пяти включённым папкам (агрегаты, без PHI). Псевдонимы вычислены установочной солью, то есть совпадают с теми, что создаёт импорт.

|---|---|

| Уникальных пациентов после дедупликации | **135** |
| Пациентов более чем в одном источнике | **33** (24%) |
| Исследований | 181 |
| Серий | 1722 |
| Пациентов с неконтрастной 3D-серией | 38 |
| Пациентов с любой 3D-серией | 39 |
| Серий уровня Extended (3D, ≤1.5мм) | 83 (4.8%) |
| Серий уровня Baseline | 1502 |
| Серий уровня Unusable | 137 |

| Постконтрастных серий распознано | 4 |

### Что из этого следует

**Дедупликация обязательна и уже спасает.** Сумма пациентов по источникам — 174, уникальных — 135. Тридцать три пациента лежат более чем в одной независимо собранной папке, то есть каждый четвёртый. Без дедупликации по DICOM-идентификаторам они оказались бы одновременно в train и test, и метрики были бы завышены без единого признака ошибки.

**Обучать DL-сегментацию не на чем.** Пациентов с пригодной неконтрастной 3D-серией — 38, серий уровня Extended — 83 из 1722. Это подтверждает решение о двух уровнях входа: подавляющее большинство выборки даёт только линейные измерения.

**Половина серий не имеет распознанной взвешенности.** 840 из 1722. Baseline-сегментация при неизвестной взвешенности отказывается работать — направление порога определить нельзя, — значит, на этих сериях она не запустится вовсе. Распознавание идёт по свободному тексту описания серии, и это его известное ограничение, а не дефект данных.

**Постконтрастных распознано всего 4.** При 840 сериях с нераспознанной взвешенностью это почти наверняка недооценка: та же эвристика по описанию. Отделение постконтрастных серий перед построением датасета требует ручной проверки на приёмке.

**Блокирующее замечание геометрии у 38% серий** — 420 с совпадающими положениями срезов и 237 с неравномерным шагом. Долю такого размера нельзя принимать на веру: либо в выборке действительно много многоэховых серий под одним `SeriesInstanceUID` (что правдоподобно и означает необходимость разделения по эхо), либо проверка совпадающих положений слишком строга для реальных данных. **Это открытый вопрос, требующий разбора на конкретных сериях до построения датасета.**

**Прежние числа (225 пациентов, 31 с 3D T1) заменены.** Они считались по шести папкам, включая исключённую.

### Состав источников

Выборка лежит на внешнем диске в независимо собранных папках. К разбору принимаются пять:

| Папка | Включена |
|---|---|
| `Ретроспективное исследование Снимки МРТ` | да |
| `От ГВ` | да |
| `От ГВ 13.01.2023` | да |
| `МРТ иНТГ` | да |
| `Для А.В. Станишевского` | да |
| `Головы` | **нет** |

`Головы` исключена решением владельца данных (2026-09-06): снимки не относятся к гидроцефалии. Исключение записано здесь, а не держится в устной договорённости, потому что папка составляет около двух третей всех файлов на диске, и инвентаризация, случайно прогнанная по всем шести, даст выборку с посторонними исследованиями — и внешне правдоподобные цифры.

**Числа в таблице выше получены до этого исключения и подлежат пересчёту.** Сколько из 225 пациентов приходилось на исключённую папку, из самой таблицы не видно; до перерасчёта считать эти значения актуальными нельзя.

Отдельно обнаружены клинические документы (выписные эпикризы), лежащие вперемешку с папками снимков в одном из источников — это потенциальный источник `reference_standard.diagnosis_class`, но его нужно извлечь в отдельную структурированную, версионированную и деидентифицированную таблицу согласно схеме выше, а не использовать как есть из папки со смешанным содержимым.

## Минимальные срезы отчётности

Метрики показываются отдельно по центру, производителю и модели сканера, напряжённости поля, протоколу, полу, возрастным группам, выраженности DESH, сопутствующей атрофии и болезни малых сосудов.
